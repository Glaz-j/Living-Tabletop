## 预检发现并修复的问题

正式批次前先执行了 16、32、64 局的递增预检。以下问题均保留了触发 seed 与单局记录，并在相同探针回归通过后才开始 1024 局：

1. **历史物品交接被当成本轮交接（产品缺陷）**：NPC 复述“刚才把小折刀递给你”时，`ItemChangeValidator` 仅按动词扫描，误认为本轮必须再次提交背包变化，导致整个回合被拒绝。校验器现会排除元语言复述与明确的回顾语境；真实的当前交接仍必须携带受控世界变更。
2. **“交给我的”被误判为玩家交还物品（测试模型缺陷）**：合成 Composer 的交还正则范围过宽。现在只接受玩家主动“我把……递还/交还”或明确“不再带”的表达。
3. **询问同行与地点名中的“去处”触发移动（测试模型缺陷）**：合成意图识别改为要求明确的第一人称动身承诺，并排除“愿不愿意”“不去”“只是问”等表达。
4. **剧情中断误报物品取得失败（测试断言缺陷）**：事件在动作提交前打断时，不再要求背包发生预期变化；仍要求状态与中断演出完整。
5. **合成回复过于单一造成重复演出噪声（测试模型缺陷）**：地点复合问题、消息来源追问、离场目标和无 NPC 场景现在生成与当前输入相关的演出；同义重复提问允许得到相同事实回答。
6. **地点回答跨场景复用罗克斯伯里路线（测试模型缺陷）**：第一次 1024 局结构审计通过后，人工复查发现医院地下室也使用了疗养院路线。地点回答现按实体 id 生成，新增回归断言保证医院场景不出现罗克斯伯里路线；修正后从空目录重新运行完整 1024 局。最终批次覆盖 2221 次地点询问，其中医院 1087 次、科比特场景 1134 次，未再发生跨场景路线污染。
7. **等价的消息来源追问被判为重复演出（测试断言缺陷）**：连续两次针对同一事实询问“亲眼看见还是听说”时，相同的直接来源回答是合理的。断言仅对这种明确等价的追问放宽，并保留其他不同意图重复演出的检测；原 seed 与额外 32 局预检均通过。

- 每局恰好 32 步、每步 `accepted=true` 且状态版本严格前进；
- 演出非空，单局玩家输入不重复；
- `no_location_change` 探针前后地点相同；
- 取得、交还、仅确认物品与背包和事件日志一致；
- 每个背包实体存在、激活、类型正确且位置属于玩家；
- WorldState 能序列化并重新通过 Pydantic 校验；
- Director 内部解释不进入玩家可见演出；
- 同一命令 `--resume` 可在不重跑单局的情况下复建最终汇总。
